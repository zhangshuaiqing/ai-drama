# 扣子（Coze）平台使用技巧与积分指南

> 整理日期：2026-05-23
> 适用平台：扣子（coze.cn）——字节跳动出品的 AI Bot 开发平台

---

## 一、平台概览

扣子是字节跳动推出的 AI Bot 开发平台，支持零代码/低代码搭建智能对话机器人（Bot），并发布到抖音、飞书、微信、Web 等多个渠道。

### 核心能力

| 功能 | 说明 |
|------|------|
| **Bot 构建** | 设定人设、触发回复，快速创建对话机器人 |
| **工作流（Workflow）** | 可视化流程编排，处理多步骤/复杂逻辑任务 |
| **对话流（Dialog Flow）** | 基于状态的对话树，适合问卷/客服分流等场景 |
| **插件（Plugin）** | 集成外部 API 能力（搜索、绘图、数据分析等） |
| **知识库（Knowledge Base）** | 上传文档/网页，Bot 基于此做专属问答 |
| **多渠道发布** | 一键发布到抖音、飞书、微信、Web API 等 |
| **AI 编程** | code.coze.cn——全代码开发智能体、应用、工作流、小程序 |

## 二、积分体系

积分是扣子平台统一计量单位，用于抵扣 Bot 调用和大模型 Token 消耗。

### 2.1 积分用途

积分可用于抵扣：
- **扣子任务费用**（Bot 运行）
- **扣子编程任务费用**（AI 编程项目运行）
- **模型费用**（大模型 Token 消耗）
- **插件费用**（第三方工具调用）
- **知识库空间费用**、**记忆库费用**、**音视频费用**等

不可抵扣：火山方舟大模型、付费技能/模板/第三方插件。

### 2.5 节省积分技巧

- 测试阶段用**便宜模型**（如豆包 mini 而非 GPT-4），消耗差几倍
- 设置单次调用积分上限，防止异常消耗
- 每日登录领的 1,500 积分虽然少，但累积下来也能跑不少测试
- 工作流中避免死循环或过度复杂的条件分支——超时也会消耗积分
- 知识库文档按需分块，不要一次上传大量无关内容

## 三、核心功能使用技巧

### 3.1 人设 Prompt 编写

Prompt 是 Bot 表现的核心。建议结构化编写，分为几个明确区块：

```
角色：你是一个xxx
任务：你需要做xxx
约束：
- 如果知识库没有相关信息，直接说不知道
- 回答控制在200字以内
- 不使用markdown格式
上下文处理：每次对话开始时，先回顾上一轮关键信息
```

### 3.2 工作流使用技巧

- **善用日志节点**：在中间节点加入日志输出，调试时比只看最终结果好用得多
- **变量传递**：用工作流变量传递中间结果，避免在 prompt 里塞太多上下文
- **条件分支简化**：分支不要超过 3-4 层，否则容易超时
- **工作流 vs 对话流的选择**：后台逻辑处理（查数据库、计算）用工作流；需要引导用户选择选项的场景（问卷、分流）用对话流

### 3.3 知识库使用要点

- 文档要**结构化分块**：按主题/段落分块，每块聚焦一个具体问题
- 块大小控制：建议每块 200-500 字，太大检索不准，太小缺乏上下文
- 格式优先：结构化文本（Markdown/表格） > PDF > Word
- 定期更新：知识库内容过期会导致 Bot 给出错误答案

### 3.4 插件使用注意事项

- 关键插件要准备 **fallback**：比如搜索失败时返回预设答案，而不是让 Bot 卡住
- 插件调用会消耗额外积分（调用次数 + Token）
- 外部 API 可能随时变更或失效——定期检查插件状态

### 3.5 发布到各渠道的注意事项

| 渠道 | 注意点 |
|------|-------|
| **抖音** | 内容要合规，回复经过自动/人工审核。配置触发词和欢迎语 |
| **飞书** | 需要配置飞书应用权限和事件订阅，回复格式适配消息卡片 |
| **微信** | 个人微信需通过企微/第三方接入，较复杂。企微需认证 |
| **Web API** | 通过 API/SDK 集成到自有系统 |
| **通用** | 所有渠道都要设置**触发词、欢迎语、未命中回复**；不同渠道对 Markdown 的支持不同，发布前做多渠道测试 |

## 四、常见踩坑点

1. **积分悄悄耗光**：用 GPT-4/4o 模型测试时消耗很快，测试阶段建议切换为便宜模型
2. **工作流超时**：逻辑过于复杂或循环嵌套太多，默认超时时间较短
3. **知识库检索不准**：文档没分好块，Bot 找不到正确资料。调整 chunk size 和检索策略
4. **插件突然失效**：第三方 API 变更或下线，导致 Bot 逻辑中断。准备 fallback
5. **模型幻觉**：接了知识库后 Bot 仍可能编造答案。Prompt 中要明确"如果知识库没有，就说不知道"
6. **发布后无人问津**：没有设置触发条件（关键词），Bot 在任何消息上都触发
7. **多渠道兼容**：不同平台对 Markdown、富文本、卡片消息的支持程度不同

## 五、推荐的入门路径

1. 注册 coze.cn → 领新用户积分
2. 从模板商店找一个感兴趣的 Bot 模板，改 prompt 试试
3. 学会用调试面板观察 Bot 的思考过程
4. 加知识库——上传一份你熟悉的文档（比如产品手册），让 Bot 回答相关问题
5. 尝试搭一条简单的工作流（比如：用户提问 → 查知识库 → 格式化回答）
6. 发到抖音或飞书测试一下实际效果
7. 根据消耗情况评估是否需要购买积分套餐
